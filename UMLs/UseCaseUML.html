SmartInventory — Use Case Diagram

Diagram A — Employee Use Cases

UC-03 extends both UC-01 and UC-02 because the actor must first locate an item (via either viewing inventory or searching) before recording a transaction.

Diagram B — Manager Use Cases

Manager inherits all Employee use cases via generalization (grey dashed UCs). UC-06, UC-08, UC-09 each extend both UC-01 (View Full Inventory) and UC-02 (Search Item) — the actor must first locate an item before performing the operation.

UC-04 (Manager Authentication) is modeled explicitly and is treated as the session precondition before manager-specific operations are executed.

Use Case Descriptions

UC-01 · View Full Inventory
UC ReferenceUC-01
OverviewActor requests a complete listing of all items. System retrieves and displays itemId, name, category, quantity, price, and threshold for every stored item.
Related Use CasesBase for UC-03, UC-06, UC-08, UC-09
ActorsEmployee; Manager (via generalization)
UC-02 · Search Item
UC ReferenceUC-02
OverviewActor enters a partial or full item name. System performs a case-insensitive substring match and returns all matching items, or reports none found.
Related Use CasesBase for UC-03, UC-06, UC-08, UC-09
ActorsEmployee; Manager (via generalization)
UC-03 · Make Transaction / Record Sale
UC ReferenceUC-03
OverviewAfter locating an item via UC-01 or UC-02, actor provides itemId and sale quantity. System validates stock, deducts quantity, records a Transaction, and auto-generates a RestockRequest if post-sale quantity ≤ threshold.
Related Use CasesExtends UC-01, Extends UC-02; auto-generates RestockRequest entries reviewed in UC-10
ActorsEmployee; Manager (via generalization)
UC-04 · Manager Authentication
UC ReferenceUC-04
OverviewManager provides credentials and the system verifies them before any manager-only operation is allowed.
Related Use CasesPrecondition for UC-05, UC-06, UC-07, UC-08, UC-09, UC-10
ActorsManager
UC-05 · Add Item
UC ReferenceUC-05
OverviewManager provides name, initial quantity, price, restock threshold, and category for a new item. System generates a unique itemId and persists the new Item to inventory.
Related Use CasesRequires UC-04
ActorsManager
UC-06 · Delete Item
UC ReferenceUC-06
OverviewAfter locating an item via UC-01 or UC-02, Manager specifies the itemId for permanent deletion. System removes the item and clears any associated RestockRequests.
Related Use CasesExtends UC-01, Extends UC-02
ActorsManager
UC-07 · Check Low Stock Alerts
UC ReferenceUC-07
OverviewManager requests a low-stock report. System evaluates isLowStock() on each item and returns all items whose current quantity is at or below their threshold.
Related Use CasesNone
ActorsManager
UC-08 · Update Item Details
UC ReferenceUC-08
OverviewAfter locating an item via UC-01 or UC-02, Manager modifies its name, price, threshold, and/or category. Stock quantity is NOT changed by this use case.
Related Use CasesExtends UC-01, Extends UC-02
ActorsManager
UC-09 · Update Stock Quantity
UC ReferenceUC-09
OverviewAfter locating an item via UC-01 or UC-02, Manager sets a new absolute stock quantity (e.g. after physical count). Distinct from UC-03 which records a sale deduction.
Related Use CasesExtends UC-01, Extends UC-02
ActorsManager
UC-10 · Review Restock Requests
UC ReferenceUC-10
OverviewManager views all pending RestockRequests auto-created by UC-03. For each, Manager may fulfil it (restocking item quantity) or skip it. Fulfilled requests are cleared from the pending list.
Related Use CasesConsumes RestockRequests generated by UC-03; requires UC-04
ActorsManager
